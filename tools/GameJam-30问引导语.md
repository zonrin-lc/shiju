### 第 9 次 · 单回合：行动卡回合制

```
承接上一轮。写单回合的微观循环，这是整个游戏最核心的机制，要写透。

事实锚（已实装，不要改数值）：
每回合发 4 张卡：关键事件卡 ×1 + 普通行动卡 ×3

【关键事件卡】
- 本章当前待触发的剧本事件，包装成卡
- 限时 3 回合（引擎常量 KEY_CARD_ROUNDS = 3）
- 每打出一张行动卡，倒计时 -1
- 被动倒计时牌：不可主动点开，只显示「余 N 轮后开启」
- 倒计时归零即自动开启该事件的抉择页
- 玩家阅读全文后必须亲自选择（不再自动循史）
- 极端情况下全选项锁定会兜底重置倒计时，防止死锁
- 设计主题：「时不我待，但历史不由机器代笔」
- 结算后回到回合，下一剧本事件成为新关键卡，倒计时回满

【普通行动卡】
- 从本章可用行动池随机抽 3 张，同轮不重复
- 每章可用池恰为 12 张
- 打出即结算属性增减
- 同一行动同章第 n 次使用收益递减：收益项按 ⌊v / 2^(n-1)⌋ 递减、下限 ±1；代价项不减
- 行动不消耗事件决策点，但会推进关键卡倒计时

【插入事件】
- 随机际遇 / 危机注入事件 / 逆天反噬 以插入方式挂入回合流
- 际遇归来后关键卡倒计时回满 3（际遇不消耗决策点）
- 危机插入事件（C-DEATH / 构陷 / 清算）以 inserted 关键卡呈现，UI 赤色描边

【章内进度】
- 顶栏显示「已通过关键事件 x / 本章事件数 n」，只有抉择结算计入

输出要求：
- 机制规格（像给程序看的那种，带字段和常量）
- 设计意图：行动卡把「等待下一个事件」的空白转化为经营属性的主动权；关键卡倒计时防止无限刷行动——拖延本身会把选择权交还给历史
- 这一节如何体现涌现：说明「玩家不刷行动、只追事件」和「玩家刷行动经营自己」是两种涌现出来的不同玩法

不要写数值系统。
```

### 第 10 次 · 收益递减与蓄势

```
承接上一轮。写两个「反刷」机制。

【收益递减】
同一行动同章第 n 次使用，收益项按 ⌊v / 2^(n-1)⌋ 递减，下限 ±1；代价项不减。
例：某行动 +10 权势 / -5 危机，第 1 次 +10，第 2 次 +5，第 3 次 +2，第 4 次 +1，第 5 次起 +1。
注意：危机是「越高越坏」的逆向属性，收益递减对它同样生效，所以反复刷行动并不能把危机刷下去。

【蓄势（策略牌）】
- 打出蓄势等于放弃本回合出牌
- 代价：下次事件抉择时，险招判定 +10
- 兑现：抉择一旦做出，蓄势立即清空
- 作用域是「下一次事件抉择」，包含随机际遇（这一点已经修订过，引擎注释以「下一次事件抉择，含际遇」为准）

```

### 第 11 次 · 险招机制

```
承接上一轮。写险招（risky choice）机制。

事实锚：
- 险招是高收益选项的软门槛，不是硬门槛
- **软门槛只对属性键生效**：选项的 req 里凡是属性键（11 维中的 5 个自身维度最常用），不达标不是禁用，而是降档
- **硬门槛保持锁定**，这些 req 键不掷骰：flag / notflag / anyflag / minChapter / devMin / devMax / weijiMax / quanshiMax / junxinMax / zgMax / junxinMaxSeen
- 行动卡语境下的 caifu 是「支付能力检查」，特判为硬门槛（付得起才能点，付不起直接锁）
- **六档成功率按「未达标差值 gap」取最低**：gap≤3→70% / ≤6→50% / ≤9→40% / ≤12→30% / ≤15→20% / >15→15%
- **史实升档**：如果选项带 hist 标记（即「按史书记载去做的事」），成功率再升一档——≥50→70 / ≥40→50 / ≥30→40 / ≥20→30 / 其余→20。设计理由：历史惯性体——玩家赌的是「改变历史」，而不是「成为历史」，后者历史不咬人
- 掷骰走独立随机流（risk 流），与事件流、际遇流分离，测试可注入常量骰
- 失败不是无事发生，而是「烧毁」：该选项标记 _burned，本局不可再选
- 硬核模式下掷骰只显示档位词，不显示具体数字

请输出：
1. 机制规格（软门槛六档的完整表、史实升档表、硬门槛键清单、行动卡 caifu 特判、烧毁语义）
2. 为什么用「软门槛 + 掷骰 + 烧毁」三层，而不是简单的属性达标/不达标
```
